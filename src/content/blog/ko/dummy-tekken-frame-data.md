이 글은 레이아웃 확인용 더미 글입니다. **철권 프레임 데이터 뷰어**에 대해 짧게 정리합니다.

## 배경

처음에는 간단해 보였지만 막상 해 보니 생각보다 손이 많이 갔습니다. 문서를 읽고, 예제를 돌려 보고, 결국 직접 코드를 뜯어 보면서 이해했습니다.

## 해결

```ts
export async function run(input: string) {
  const result = await process(input);
  if (!result.ok) throw new Error(`실패: ${result.reason}`);
  return result.value;
}
```

핵심은 `process`가 실패를 예외 대신 값으로 돌려준다는 점입니다.

- 에러를 값으로 다루면 흐름이 읽기 쉬워진다
- 재시도 로직을 한곳에 모을 수 있다
- 테스트가 단순해진다

## 비교

| 방식 | 장점 | 단점 |
| --- | --- | --- |
| 예외 | 코드가 짧음 | 흐름 추적이 어려움 |
| 결과 값 | 명시적 | 코드가 길어짐 |

> 결국 정답은 없고, 팀이 읽기 쉬운 쪽을 고르면 됩니다.

긴 글에서 스크롤과 줄 길이가 어떻게 보이는지 확인하기 위한 문단입니다. 한 줄에 한글이 몇 자 들어가는지, 줄 간격이 편안한지, 코드 블록과 본문의 대비가 적당한지 살펴봅니다. 같은 문장을 반복해서 문단을 길게 만듭니다. 한 줄에 한글이 몇 자 들어가는지, 줄 간격이 편안한지 살펴봅니다.
